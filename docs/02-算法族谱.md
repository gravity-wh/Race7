# 02 · 算法族谱：九类可用的 LU 加速算法

> 本篇把"能把 LU 做快同时保住精度"的算法排成族谱，每类标注：**降了哪个精度槽位**、
> **误差靠什么控制**、**加速上限**、**适用条件**。最后给一张横向对比表。

## 2.0 谱系

```
精度分层的 LU
├─ A. 直接法内循环（改 LU 本身）
│   ├─ A1 定常迭代精化 (IR)                    —— 降 u_f，靠不动点收缩
│   ├─ A2 三精度 IR (Carson–Higham)            —— 形式化 u_f / u / u_r
│   ├─ A3 GMRES-IR / FGMRES-IR                 —— 降 u_f，靠 Krylov 求修正
│   ├─ A4 分块（tile/递归）LU                   —— panel 与 update 分别定精度
│   ├─ A5 通信避免 LU (CA-LU)                   —— 降的是通信，不是精度（可组合）
│   └─ A6 随机化/草图 LU                        —— 把 n³ 降成 n²·k
├─ B. 精度补偿计算（不改 LU，改乘加）
│   ├─ B1 Ozaki 拆分（无误差变换）              —— 用低精度 GEMM 模拟 FP64
│   ├─ B2 双倍-双精度 / 补偿 GEMM               —— FP32 对拼出 ~48–53 位
│   └─ B3 低秩补偿（Woodbury）                  —— 修正被量化掉的因子误差
└─ C. 把 LU 当预条件（不求精确解）
    ├─ C1 低精度 ILU + Krylov                   —— 只求"够好的预条件"
    └─ C2 多重网格 + 低精度粗网格 LU            —— LU 只在小规模上出现
```

## 2.1 A 类：改 LU 本身

### A1 定常迭代精化（IR）

最古老也最便宜的一条（Wilkinson 1963；LAPACK 的 `xGERFSX` 至今在用）。
给定低精度因子 `M = L̂Û`，反复做

```
r ← b - Ax          （高精度）
d ← M⁻¹ r           （低精度三角求解）
x ← x + d           （工作精度）
```

误差递推为 `e_{k+1} = (I - M⁻¹A) e_k + M⁻¹Δr`，收缩条件是 `‖I - M⁻¹A‖ < 1`，
充分条件约 `κ(A)·u_f < 1`。极限前向误差 `≈ κ·u`（工作精度），与 `u_f` 无关——
**这就是"低精度分解 + 高精度结果"的全部秘密**。

- 降的槽位：`u_f`（以及可选的 `u_t`）
- 代价：每步 `4n²`（两次三角求解 + 一次残差），`O(n²)`
- 致命弱点：收缩是**线性**的，`κ·u_f` 一旦接近 1，收敛因子接近 1，迭代数爆炸；
  超过就发散（不是"慢"，是"发散"）。

### A2 三精度 IR

Carson & Higham（[SIAM J. Sci. Comput. 2018](https://epubs.siam.org/doi/10.1137/17M1140819)）
把 A1 里的精度显式分成三个角色：**分解 `u_f`、工作 `u`、残差 `u_r`**，并给出
"极限前向误差 ~ `u`"与"向后误差 ~ `u_r`"的界。工程价值在于：它把"哪些运算必须高精度"
变成了一张可查的表，而不是靠经验。

| 运算 | 精度 | 理由 |
|---|---|---|
| LU 分解 | `u_f`（可很低） | `O(n³)`，加速比来源 |
| 三角求解 | `u` | `O(n²)`，降了也省不了多少 |
| 残差 | `u_r`（必须高） | 决定可达精度，且是精化的"锚" |
| 更新 `x+d` | `u` | 同上 |

### A3 GMRES-IR / FGMRES-IR ★

把 A1 里的 `d ← M⁻¹r` 换成"**用 GMRES 解 `A M⁻¹ z = r`，再令 `d = M⁻¹z`**"。
这个改动看似只是换了个求解器，实则改变了收敛的**判据类型**：

- A1 要求 `M⁻¹` 是一个**收缩映射**（`‖I - M⁻¹A‖ < 1`）；
- A3 只要求 `M⁻¹` 是一个**有界预条件**（`‖AM⁻¹ - I‖` 有界），GMRES 自己在
  Krylov 子空间里找下降方向。

本文实测（[04](04-实验证据.md)）：FP32 因子 + FP64 GMRES-IR 在 `κ` 从 1 到 `1e14`
的整个区间都把前向误差压回 FP64 水平，内层迭代从 4 步涨到 ~107 步（n=64）；
而定常 IR 在 `κ=1e9` 就崩溃。代价是每步的内层迭代是 `O(n²)` 的 Krylov 扫描。

> **这是本文推荐的默认方案。** 它把"可用条件数"从 `1/u_f` 推到 `1/u_r`，
> 代价是 `O(log κ)` 量级的迭代数，而迭代数是 `O(n²)`，相对 `O(n³)` 的分解可以摊销。

FGMRES 变体用于预条件本身每次都在变的情形（例如内层也用低精度、或预条件带随机性）。

### A4 分块 / 递归 LU：面板-更新分离

把 LU 切成 `[A11 A12; A21 A22]`：

```
A11 = L11 U11            (panel，O(nb³) 或 O(n·nb²))
L21 = A21 U11⁻¹          (trsm)
U12 = L11⁻¹ A12          (trsm)
A22 ← A22 - L21 U12      (GEMM，占 90%+ 的 flops)
```

**这个结构天生适合精度分层**：`A22` 的更新是 `O(n³)` 的主要部分，可以放到低精度阵列；
面板分解是 `O(n·nb²)`，留在高精度。于是"降精度"只发生在最贵的那一步，
而"精度锚点"（面板主元、增长因子）仍在高精度下计算。见 [06](06-加速器映射.md) 的设计规则 R3。

工程上这就是 LAPACK 的 `getrf` 分块、MAGMA 的 `getrf_mgpu`、以及所有 tensor-core LU 的骨架。

### A5 通信避免 LU（CA-LU）

把 `k` 步消元合并成一次"计算 `A^{-1}` 的 k 步块"（涉及 `s`-步 Krylov / 矩阵幂），
用更多的 flops 换更少的同步。它降的不是精度，而是**通信**，因此与 A1–A4 **正交可组合**：
CA-LU + 低精度 += 两个维度的收益。风险是数值稳定性更差（中间量放大），
在 `κ` 大时需要额外的精化兜底。

### A6 随机化 / 草图 LU

用随机投影 `Ω` 把 `A` 压成 `(n × k)` 的草图，在草图上做 LU 得到近似因子。
代价从 `O(n³)` 降到 `O(n²k)`。适合**低秩 + 稀疏**结构，通常只当预条件用。
误差是概率性的，需要精化兜底；在"只要预条件、不要精确解"的场景（C 类）里更有价值。

## 2.2 B 类：精度补偿计算（不改 LU 的语义）

A 类的思路是"算得糙，再用残差修"；B 类的思路是"**用多次低精度运算拼出高精度运算**"。
两者是竞争关系，选择取决于硬件是否有高精度单元。

### B1 Ozaki 拆分（无误差变换）

把每个 FP64 数拆成若干段低位宽"切片"（例如 3 段 24 位，或 7 段 8 位），
把 FP64 GEMM 变成 **k² 次低精度 GEMM**，在整数域里精确累加，最后拼回。
在 INT8 张量核上模拟 FP64 已有成熟实现（Ootomo–Ozaki 系列工作），
在"没有 FP64 单元"的硬件（消费级 GPU、AI 加速器）上是唯一可行的路径。

- 优点：不需要任何 FP64 算术单元；精度可证明。
- 缺点：`k²` 倍的低精度 flops；`k=3` 时是 9 倍 FP32 量，只有在
  "低精度 : FP64 吞吐 ≥ 9 : 1"的硬件上才划算。
- 与 A 类的关系：Ozaki 做**分解**，A3 做**精化**，两者可以叠加（"用 Ozaki 算 FP64 残差"）。

### B2 双倍-双精度 / 补偿 GEMM

两个 FP32 拼成 ~48 位（`hi + lo`），用 4 次 FP32 乘法 + 误差项得到接近 FP64 的乘加。
比 Ozaki 简单，精度略低（48 vs 53 位），适合"FP32 快但 FP64 慢"的 GPU。
本质是 **Kahan 补偿思想在 GEMM 上的推广**。

### B3 低秩补偿（Woodbury）

把量化误差矩阵 `E = A - M` 做截断 SVD：`E ≈ U_r Σ_r V_rᵀ`，于是

```
M_c = M + U_r Σ_r V_rᵀ   ⇒   M_c⁻¹ = M⁻¹ - M⁻¹U_r (Σ_r⁻¹ + V_rᵀM⁻¹U_r)⁻¹ V_rᵀM⁻¹
```

每次应用只多 `O(nr)`，不需要重分解。**注意**：本文实验表明，`E` 通常是满秩的、
且在病态方向上能量最大，低秩补偿对"事后量化"的因子几乎无效；
它真正有用的场景是**残差不可得**（例如模拟存内计算，无法在 FP64 下重算 `b - Ax`）。

## 2.3 C 类：把 LU 当预条件

### C1 低精度 ILU + Krylov

稀疏场景的主流：不完全 LU 在低精度下算（Scott & Tůma 讨论了半精度下的 breakdown 与
[溢出规避](https://arxiv.org/abs/2401.17957)），外层用 GMRES/BiCGStab 在 FP64 下迭代。
精度要求低（预条件只要能加速收敛），是"量化"最容易落地的地方。

### C2 多重网格 + 低精度粗网格 LU

`LU` 只在粗网格（小 `n`）上用，甚至可以在低精度下用。
粗网格的 `κ` 小、规模小，是低精度最安全的落点。

## 2.5 本篇小结

1. **A3（GMRES-IR）是通用场景的默认选择**：它把可行域从 `1/u_f` 扩到 `1/u_r`。
2. **A4（分块）是硬件落点**：`O(n³)` 的 GEMM 降精度，`O(n·nb²)` 的面板保精度。
3. **B 类是与 A 类竞争的路线**，选择取决于"有没有高精度单元"而非算法优劣：
   有 FP64 单元 → 用 A3（残差 `O(n²)` 极便宜）；没有 → 用 B1（用 `k²` 次低精度换精度）。
4. 剩下所有算法都可以看成这三条的变体或组合。
