# 10 · 四级消融实验清单（可执行）

> **目标**：把"比厂商稀疏 LU 慢的倍数"拆成四项**乘性因子**，判断差距里多少是算法空间、
> 多少是硬件上限。每一项都是"只动一个变量、其余固定"的测量，因此可乘、可复现。

```
总差距 = (fill_ours / fill_best)          ← A 排序/填充        （算法）
       × (t_flop_ours / t_flop_best)      ← B 分块/BLAS3      （实现）
       × (t_pivot_ours / t_pivot_static)  ← C 主元策略        （稳定性代价）
       × (1 / eff)                        ← D 核效率 vs 屋顶线（硬件判据）
```

## A. 排序 / 填充（算法空间的上界）

**变量**：排序方案。**固定**：主元策略、分块、精度。

| 方案 | 怎么跑 |
|---|---|
| 全局 AMD，无 BTF | `./omega <mtx> 0 0 0` |
| BTF + 块内 AMD | `./omega <mtx> 1 0 0` |
| 自然序（不排序） | 加 `ord=none`（需 ~10 行，直接用 0..n-1） |
| 自研 mindeg | `glu_test --matrix=<mtx>` 的符号阶段 |

**命令**（在服务器 `/tmp/om` 下）：
```bash
for f in ~/PublicCase/GLU_public/src/matrix/*.mtx; do
  echo "== $(basename $f)"
  ./omega $f 0 0 0 | sed 's/^/  nat: /'
  ./omega $f 1 0 0 | sed 's/^/  btf: /'
done
```

**预期输出**（CSV）：`matrix, order, nnzA, nnzLU, fill_ratio, rho, t_sym, t_num`

**判据**：
- `fill_ratio = nnz(L+U)/nnz(A)`，与排序强相关；
- 若 `fill_best/fill_worst ≥ 3` → **排序是第一瓶颈**，A 项倍率 = `nnzLU_ours / nnzLU_best`；
- 已知锚点：`rajat25` 在 `btf=0` 为 7.2M、`btf=1` 为 42.5M，**6× 差异，且 ρ 从 37.7 变到 6.9e7**。

**注意**：BTF 同时改变填充**和**数值增长，所以这一步要同时记 `ρ`，否则会把数值问题误记成排序问题。

## B. 分块 / 超节点（BLAS3 占比）

**变量**：分块宽度 `b`、超节点开关。**固定**：A 步选出的最优排序。

| 参数 | 位置 |
|---|---|
| `b ∈ {32, 64, 128, 256}` | 自研内核的分块常量（`glu_numeric_cpu.c` / `.cu`） |
| 超节点 on/off | 符号阶段的 `super_ptr` 生成 |

**命令**（每改一次 `b` 要重编）：
```bash
for b in 32 64 128 256; do
  make clean >/dev/null && make CFLAGS="-O3 -DBLOCK=$b" >/dev/null 2>&1
  for f in rajat25 twotone ASIC_100k; do
    ./build/glu_test --matrix=$M/${f}_csr.mtx --quiet --csv=/tmp/b${b}_${f}.csv
  done
done
```

**预期输出**：`b, matrix, t_factor, GFLOPS`

**判据**：
- `GFLOPS(b)` 应在某个 `b*` 饱和；`b*` 之后填充爆炸，时间回升；
- B 项倍率 = `t_flop(b=1) / t_flop(b*)`（用"标量核"作参照，可用 `b=1` 或他们的 scalar 路径）；
- 若 `b*` 处 GFLOPS 已接近 D 步的屋顶线 → 分块没有更多空间。

## C. 主元策略（稳定性的代价）

**变量**：部分主元 vs MC64 匹配 + 静态主元。**固定**：A 的排序、B 的 `b`。

**输入**：优先 `rajat25/26/27`（`ρ` 大的），再加 2 个 `ρ≈1` 的作对照。

**命令**：
```bash
# 部分主元（KLU 默认 tol=0.001）
./omega $M/rajat25_csr.mtx 0 0 0
# 静态主元：加 tol=1.0（只在对角内选主元），~5 行
./omega $M/rajat25_csr.mtx 0 0 0 --tol=1.0
```

**预期输出**：`matrix, pivoting, t_num, rho, residual`

**判据**：
- C 项倍率 = `t_partial / t_static`；
- **同时看 `ρ` 和残差**：若静态主元让 `ρ` 涨 10× 以上，说明这是"精度换速度"的显式交易，要写进论文；
- 若 `t_partial ≈ t_static`，说明主元不是瓶颈，C 项记为 1。

## D. Roofline（硬件判据）

### D0. 先补带宽实测（缺这个整条链断掉）

`lu_bench_gpu.cu` 加一个 stream 内核（读+写 2×N×8 字节），得到 `B` (GB/s)。
**没有 B，Roofline 的斜线画不出来。**

### D1. 计算每个矩阵的 AI 与实测点

```bash
# flops：用 lu_cmd 的计数或 2/3 n^3（稠密块估计）
# bytes：12 × nnz(L+U)   （8B 因子 + 4B 索引）
AI = flops / bytes
```

**画图**：横轴 `AI`（对数），纵轴 `GFLOP/s`（对数），两条线：
```
y = B × AI          （带宽屋顶）
y = P_peak          （算力屋顶：FP32 2.82 / FP64 1.24 TFLOP/s）
```

**判据（这是全清单的核心）**：

| 点的位置 | 结论 | 后续 |
|---|---|---|
| 贴带宽线（差 <2×） | **硬件限制** | 只能降流量：降精度存因子、降 fill |
| 在两线之间（差 2–10×） | 实现空间 | B 步还有收益 |
| 贴算力线 | 算力限制 | 降精度换更快的 ALU 才有效 |

## G. 风险与陷阱

1. **耦合**：改排序会同时改 fill、`ρ`、分块机会。每次只动一个，其余写进日志。
2. **基线定义**："慢 100×" 是相对谁？必须写明（厂商库的公开数据 / 旧机实测 / 理论下界），否则倍率无意义。
3. **测量噪声**：共享机器，取 3 次最小，并记录 `nproc` 与负载。
4. **fill 不是唯一**：`ρ` 大的矩阵时间也长，但那是数值问题不是填充问题——A 步必须同时记 `ρ`。
5. **别用"贴着屋顶线"证明硬件到头**：只能证明"在当前 fill/带宽下到头"，换排序可能把点右移。

## A · 第一轮结果（btf=0 全局 AMD vs btf=1 分块 AMD）

数据：`results/ablation_A.csv`；工具 `~/omega/omega`（服务器，持久化）。

| 矩阵 | fill 无 BTF | fill 有 BTF | 差距 `max/min` | ρ(BTF) |
|---|---|---|---|---|
| rajat25 | 7,163,573 | 42,492,081 | **5.93×** | 6.9e7 |
| rajat13 | 64,748 | 39,678 | 1.63× | 1.00 |
| rajat27 | 225,522 | 162,754 | 1.39× | 2.1e4 |
| rajat26 | 503,440 | 376,378 | 1.34× | 1.11 |
| ASIC_680ks | 5,218,738 | 4,459,191 | 1.17× | 1.00 |
| ASIC_100k | 4,051,453 | 3,603,610 | 1.12× | 1.00 |
| 其余 6 个 | — | — | **1.00×** | ≈1 |

### 结论 1：排序/填充 **最多只能解释 6×**，多数矩阵为 1×

7 个矩阵上 BTF 开关对 fill 完全无影响（1.00×）。最大的是 rajat25 的 5.93×。
**因此 A 项倍率 ≤ 6，单靠排序无法解释 100× 的差距**——嫌疑指向 B（分块）和 D（核效率）。

这本身是有价值的负面结果：它排除了"我们只是排序没做好"这个最容易想到的解释。

### 结论 2：BTF 对 rajat25 是**反向**的

`rajat25` 关掉 BTF 反而 fill 少 6 倍、`ρ` 从 6.9e7 降到 37.7。
说明"BTF 总能减少填充"是错的——对这条矩阵，块内 AMD 把结构打散了。
现有启发式（`fill > 20·nnz` 就关 BTF）在这条矩阵上是**正确**的，但它靠的是预测而非原理。

### 遗留

- **缺"自然序"**：本轮的两种排序都还算合理，真正的坏排序（不排序）没测。
  若自然序的 fill 比最优大 10× 以上，A 项倍率的结论要改。需加 `ord=none`（~10 行）。
- `twotone` 在 btf=0 下 100s 超时，未计入。

## D · 第一轮结果：带宽与算术强度（判据已立）

### D0 带宽（`lu_bench_gpu`，stream 内核，3 次取最小）

| 内核 | n=2^24 | n=2^25 | n=2^26 |
|---|---|---|---|
| FP32 stream | 308.6 GB/s | 839.8 GB/s | **874.9 GB/s** |
| FP64 stream | 629.2 GB/s | 1430.5 GB/s | **1445.6 GB/s** |

**FP64 反而比 FP32 高 65%**——同样元素数、双倍字节。说明 FP32 内核是
**元素/指令吞吐受限**，不是带宽受限。因此取 **B ≈ 1.45 TB/s** 作为带宽上界，
FP32 的 875 GB/s 是"小核跑不满"的证据，不是内存上限。

### D1 算术强度（按因子密度折算 flops）

| 矩阵 | n | fill | AI (FLOP/B) | 区域 |
|---|---|---|---|---|
| rajat25 | 87,190 | 42.5M | 4,844 | **compute** |
| G2_circuit | 150,102 | 20.1M | 8,339 | **compute** |
| dianwangmatrix2 | 126,905 | 9.07M | 7,050 | **compute** |
| bcircuit | 68,902 | 1.03M | 3,828 | **compute** |
| ASIC_680ks | 682,712 | 4.46M | 37,928 | **compute** |

Ridge point（用实测峰值）= `P32/B = 2.82e12/1.45e12 = 1.95 FLOP/byte`。
所有矩阵的 AI 都在 `10^3–10^4`，**比 ridge 高三个数量级 → 铁定算力受限**。

### 结论 3：这张卡上稀疏 LU 是**算力受限**，不是带宽受限

三条推论：
1. **降精度的收益来自算力**（FP32 快 2.3×），**不是来自省带宽**——所以 `s₁₆=2.34`（只降存储）没用，
   和 §5 的实测完全吻合；
2. "降存储减半流量"这类优化**在本卡上没有意义**；
3. 带宽受限的分支要等 fill 再大 3 个数量级或带宽再低才出现——**在本问题规模内不存在**。

### 结论 4：算力受限但不等于"硬件到顶"

实测 GEMM 只有 **2.82 TFLOP/s**，而一张 1.45 TB/s 带宽的卡，合理峰值应在
10–30 TFLOP/s。若峰值取 20 TFLOP/s，我们的核只跑到 **14%**。
**14% 说明这是实现空间，不是硬件上限**——D 的纵向缺口（1/eff ≈ 7）正是 B/C 还值得做的理由。

### 遗留

- 峰值是**未知量**：需要厂商规格书或一个高利用率基准（如 hcBLAS SGEMM）来定 `P_peak`。
  在拿到之前，eff 只能给区间（0.1–0.3）。
- AI 的 flops 是**密度折算估计**，不是实测计数；需用 `lu_cmd` 的 flop 计数替换（~20 行）。

## D · 第二轮：P_peak 钉死了，结论反转

hcBLAS 稠密 GEMM（`code/hcblas_bench.cu`，n=4096，4 次取最小，首轮预热）：

| 精度 | 实测 |
|---|---|
| SGEMM | **29.03 TFLOP/s** |
| DGEMM | **28.79 TFLOP/s** |

### 结论 5（关键）：这张卡 FP64 ≈ FP32，`s₃₂ ≈ 1.01`

| 来源 | s₃₂ |
|---|---|
| 我的朴素 GEMM（`lu_bench_gpu`） | 2.288 |
| **hcBLAS 稠密 GEMM** | **1.008** |

之前那个 2.29 是**朴素内核**的数——FP32 被 875 GB/s 的元素吞吐限制，FP64 反而打满了 1446 GB/s。
一旦用成熟的 GEMM 实现，**两种精度的算力几乎完全相同**。

**所以：在本卡上，"降精度换速度"这条路在算力层面不存在。**
FP32/FP64 的比值是 1.008，不是 2.3。混合精度只能换来
（a）内存容量、（b）11 位张量核（若可达），不能换来 FP64→FP32 的加速。

### 结论 6：Ridge point 修正为 20 FLOP/byte

`P/B = 29.03e12 / 1.446e12 = 20.1 FLOP/byte`（之前用朴素峰值算成 1.95，低了 10 倍）。

矩阵的 AI（10³–10⁴）仍高于 20 约两个数量级 → **算力受限的结论不变，而且更稳**。

### 结论 7：核效率 = 9.7%，实现空间约 10×

我们的 LU 内核实测 2.82 TFLOP/s ÷ 29.03 = **9.7%**。
`1/eff = 10.3`，这是 D 项的倍率。

### 归因账（更新）

| 因子 | 倍率 | 依据 |
|---|---|---|
| A 排序/填充 | ≤ 5.9×，多数 1× | fill 实测 |
| **D 核效率** | **10.3×** | 2.82 vs 29.03 TFLOP/s |
| B 分块 | 待测 | — |
| C 主元 | 待测 | — |
| **A×D** | **≈ 60×** | 已覆盖 100× 的大部分 |

### 对论文的影响（必须改）

§5 的 `s₁₁*` 门槛表用了 `s₃₂ = 2.288`。真实可达值是 **1.008**，则：
`s₁₁* = 1/(1/s₃₂ − 6Δk/n)` 的分母变成 `≈0.992 − 6Δk/n`，
对 `κ=1e8, n=4096`：`1/(0.992−0.161)=1.20`。门槛从 3.62 掉到 1.20。
**含义**：只要 11 位内核比 FP64 快 20%，就该用它——门槛极低，因为 FP32 本身不省算力。

## C · 主元策略（静态 vs 部分主元）

`omega <mtx> 0 0 0 <tol>`，`tol=0.001` 部分主元，`tol=1.0` 静态/对角主元。全局 AMD（btf=0）。

| 矩阵 | fill(部分) | fill(静态) | fill 代价 | ρ(部分) | ρ(静态) | ρ 收益 |
|---|---|---|---|---|---|---|
| rajat25 | 7.16M | 27.63M | **3.86×** | 37.7 | 1.94 | **19×** |
| rajat26 | 503k | 650k | 1.29× | 33.6 | 1.14 | 29× |
| rajat27 | 226k | 267k | 1.18× | 37.7 | 1.94 | 19× |
| G2_circuit | 20.1M | 20.1M | 1.00× | 1.004 | 1.004 | — |
| bcircuit | 1.03M | 1.03M | 1.00× | 1.000 | 1.000 | — |
| ASIC_100k | 4.05M | 4.05M | 1.00× | 1.000 | 1.000 | — |

### 结论 8：主元策略是**显式的 fill ↔ 稳定性交易**，且只在病态矩阵上发生

- 三个 `rajat` 矩阵：换静态主元，fill 涨 1.18–3.86×，但 `ρ` 降 19–29×；
- 三个良态矩阵：**完全无影响**（fill 与 ρ 都不变）。

**含义**：主元策略不是普适的优化项，它是一个**针对病态矩阵的开关**。
在 `ρ≈1` 的矩阵上折腾主元是白费；在 `ρ≫1` 的矩阵上，它是"用填换算术稳定性"的交易。

### 结论 9：C 的倍率取 1（保守）或 3.86（悲观）

因为部分主元在 fill 上更优、ρ 也可接受（37.7 远小于 1/√u），**没有理由换静态主元**。
所以 C 项倍率 = **1.0**——主元策略不是我们慢的原因。

## B · 分块（TILE 消融，n=1024，同一内核只改块宽）

| TILE | FP64 (GF/s) | FP32 (GF/s) | s₃₂ | 相对 T=8 |
|---|---|---|---|---|
| 8 | 1335.0 | 1782.5 | 1.34 | 1.00× |
| 16 | 1455.8 | 2694.9 | 1.85 | **1.51×** |
| 32 | 1180.7 | 2654.1 | 2.25 | 1.49× |
| 64 | — | — | — | 共享内存超限，失败 |

### 结论 10：分块只值 **1.5×**，且只对 FP32 有效

FP32 从 1782 涨到 2695（+51%），在 `TILE=16` 就饱和；FP64 完全没收益（甚至变差）。

**即使最优分块，也只有 2.69 TFLOP/s = hcBLAS 的 9.3%。**
所以分块**解释不了**那 10× 的效率差距——它只能解释其中的 1.5×。

### 结论 11：剩下的 ~6.9× 是"更深的核工程"

hcBLAS 到 29 TFLOP/s，靠的是寄存器分块、向量化、流水线、张量核——这些不是"调块大小"能拿到的。

### 结论 12：差距的 ~90% 是**核工程**，不是算法，也不是硬件

- 算法（排序 + 主元）最多贡献 5.9×，典型矩阵上是 1×；
- 硬件：`AI(10³–10⁴) ≫ ridge(20)`，**算力受限但远未到顶**（9.3% 利用率）；
