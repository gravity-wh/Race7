# 01 · 问题重构：从"权重量化"到"求解器精度分层"

> 本篇回答一个前置问题：**当我们说"对 LU 分解做 FP32/FP64 混合精度量化"时，量化的是什么？**
> 如果照搬神经网络量化的语言（权重 / 激活 / 累加器），会得出错误的设计结论。本篇给出一个更贴合的抽象。

## 1.1 为什么不能照搬"权重量化"

神经网络的量化有明确的静态对象：权重张量 `W` 存成 INT8/FP16，激活逐层动态量化，
矩阵乘的累加器保持高精度。误差传播是**逐层、有界、可用统计量描述**的：
`y = Wx` 的一次舍入误差不会因为 `κ(W)` 大而被放大——因为 `W` 是数据，不是算子。

LU 分解不同，它没有"权重"。它产出的是**算子**：`A = LU`（更准确地说 `PA = LU`）。
求解 `Ax = b` 时，实际被使用的是 `M⁻¹ = U⁻¹L⁻¹P`。因子误差 `E = A - M` 会经过
`M⁻¹E` 放大，放大倍数由 `κ(A)` 决定：

```
前向误差  ‖x̂ - x‖ / ‖x‖  ≲  κ(A) · (因子的向后误差)          (1)
```

**这就是 LU 与神经网络量化的第一个本质差别：误差被条件数放大，而不是被层数累加。**
一个在 `κ=10` 上"看起来只有 1e-7 误差"的 FP32 方案，在 `κ=10⁸` 上会变成 10 量级的
垃圾解——这不是精度不够，而是**算子求逆把相对误差转成了绝对灾难**。

由此得到第一条设计约束：

> **约束 C1：任何"低精度 + 无补偿"的 LU 方案，其可用条件数上界约等于 `1/u_f`。**

`u_f` 是分解所用的单位舍入。FP32 的 `u_f = 2⁻²⁴ ≈ 6e-8`，于是 `κ ≲ 1.7e7`。
这条约束在 [04 篇](04-实验证据.md) 中被实验精确验证（实测断崖在 1e8 与 1e9 之间）。

## 1.2 正确的抽象：四个精度槽位

LU 求解的执行时间由两部分构成，量级差一个 `n`：

| 阶段 | 计算量 | 数据量 | 是否值得降精度 |
|---|---|---|---|
| 分解 `PA = LU` | `(2/3)n³` | `n²` | **是**，全部加速比来自这里 |
| 三角求解 `U⁻¹L⁻¹Pb` | `2n²` / 次 | `n²` | 无所谓，占比极小 |
| 残差 `r = b - Ax` | `2n²` / 次 | `n²` | **否**，必须高精度 |
| 更新 `x ← x + d` | `n` | `n` | 否 |

于是"量化"的正确对象是**四个可以独立选精度的槽位**，而不是一个张量：

```
u_f   分解精度   —— 决定 O(n³) 主循环的算力，决定加速比，也决定可用 κ 上界
u_s   因子存储精度 —— 决定 n² 的容量与带宽（L、U 要不要压成 FP32 存？）
u_t   三角求解精度 —— 决定每次修正的代价；通常等于工作精度
u_r   残差/更新精度 —— 决定"能恢复到的最高精度"，是精化的锚点
```

用文献的语言（[Higham & Mary, Acta Numerica 2022](https://hal.science/hal-03537373)），
`u_f` 与 `u`（工作精度）与 `u_r`（残差精度）构成"三精度"框架；本文把它扩展为四槽位，
因为**存储**在现代加速器上是独立的一维（容量与带宽），而它恰好是"量化"最自然的落点。

## 1.3 三个必须回答的问题

把四槽位摆开之后，整个研究方向可以收敛成三个可判定的问题：

**Q1（可行性）** 给定 `κ(A)` 和目标精度 `ε`，`u_f` 最低能压到多少？
—— 这决定了加速比的上限：`u_f = FP32` 对应 2×，`u_f = 11 位（TF32/FP16）` 对应 8×。
本文的实验给出了一条**经验相边界**，见 [03](03-误差理论与可行域.md) 与 [04](04-实验证据.md)。

**Q2（补偿方式）** 当 `u_f` 不够时，用什么把精度"买回来"？
—— 两条路线：① 迭代精化（把解当迭代点，用高精度残差驱动）；② 误差补偿计算
（Ozaki 拆分 / 无误差变换，用多次低精度乘加模拟高精度乘加）。
两者的代价结构完全不同，见 [02](02-算法族谱.md) 第 2.3 节。

**Q3（硬件落点）** 高精度单元要放在哪里、占多少面积？
—— 关键观察：**残差通路只需要 `O(n²)` 的算力，却能决定 `O(n³)` 主阵列的精度上限**。
这直接支持"主阵列全 FP32、只留一条 FP64 精化通路"的架构，见 [06](06-加速器映射.md)。

## 1.4 一个反直觉的结论（先说结论）

"量化"在 LU 上不是免费的午餐，也不是纯粹的性能妥协，它有一个**副作用是正向的**：

> 低精度分解会把矩阵的**小奇异值方向"抹平"**（`σ_min(M) ≳ u_f‖U‖`），
> 相当于自动做了一次 Tikhonov 正则化。这使得 `‖M⁻¹‖` 不再随 `κ` 线性增长，
> 预条件算子 `AM⁻¹` 的偏差被"封顶"。

这个现象（本文 [04](04-实验证据.md) 第 4.4 节的实测，图 4/图 5）解释了
**为什么 GMRES 型精化能把可用条件数从 `1/u_f` 推到 `1/u_r`** ——
它要的不是"准确的因子"，而是"有界的预条件"。

它同时给出了一条非常具体的工程规则，也是本文最想让人记住的一条：

> **不要"压缩"高精度算出来的因子，要在目标精度下重新分解。**
> 前者保留了病态谱（`‖M⁻¹‖ ~ κ`）却引入了相对误差，后者自带正则化。
> 实测：11 位重算的因子能把 GMRES 精化推到 `κ=1e14`；把 FP64 因子压到 11 位只能到 `1e10`。

## 1.5 本篇小结

| 问题 | 结论 |
|---|---|
| 量化的是什么 | 四个精度槽位 `(u_f, u_s, u_t, u_r)`，不是张量 |
| 加速比来自哪 | 只有 `u_f`（`O(n³)`）；其余三个是 `O(n²)` |
| 精化能不能"创造"精度 | 不能，只能把误差拉回到 `κ·u_r` 的水平 |
| 可用 κ 上界 | 无精化 `≈1/u_f`；定常精化 `≈1/u_f`；GMRES 精化 `≈1/u_r` |
| 什么时候该压缩因子 | 几乎不该；要在低精度下重算 |
