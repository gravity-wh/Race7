# 06 · 加速器映射：把"精度槽位"落到硅上

> 本篇把前五篇的结论翻译成硬件约束：哪些单元要重复、哪些只要一份、面积怎么分、
> 数据流怎么排。目标是一句话——**高精度单元只需要出现在 `O(n²)` 的通路上。**

## 6.1 槽位 → 单元

| 槽位 | 计算量 | 硬件要求 | 面积占比（估计） |
|---|---|---|---|
| `u_f` 分解主循环 | `(2/3)n³` | 大阵列，FP32 或更低 | **90%+** |
| `u_f` 面板分解 | `O(n·b²)` | 小阵列，可高精度 | <5% |
| `u_t` 三角求解 | `2n²`/次 | 向量通路，工作精度 | <2% |
| `u_r` 残差 | `2n²`/次 | **必须 FP64**，向量通路 | <3% |
| 控制（κ 估计、收敛判据） | `O(n²)` | 标量/向量，FP64 | <1% |

关键的数量级：`n=4096` 时，分解是 `4.6e10` flops，而一次 FP64 残差只有 `3.4e7`——
**相差 1300 倍**。即使做 100 步精化，FP64 的 flops 也只占总量的 7%。

## 6.2 面积与能耗的数量级

| 运算 | 相对面积/FMA | 相对能耗/FMA | 说明 |
|---|---|---|---|
| FP64 FMA | 4× | 3–4× | 53 位尾数 + 规格化 |
| FP32 FMA | 1× | 1× | 基准 |
| TF32/FP16（张量核） | ~0.25×（摊到 MAC） | ~0.2× | 靠阵列复用摊薄 |
| INT8 | ~0.1× | ~0.1× | 同上 |

（数量级参考 NVIDIA A100/H100 的 SM 布局；不同工艺差别很大，用于做预算而非精确估算。）

由此得到"最小 FP64 足迹"的算法：

```
FP64 需要的算力占比 ≈ (k·2n²) / (2/3·n³) = 3k/n
面积占比         ≈ 4 × 3k/n = 12k/n
```

`k` 是精化步数。对 `n=4096, k=14`：FP64 算力占比 1%，面积占比 ~4%。
对 `n=256, k=14`：算力占比 16%，面积占比 ~65%——**小规模时 FP64 反而更贵**。

**时间侧的同一枚硬币**（[04 篇 4.8](04-实验证据.md)）：`k` 步精化的代价 = `6k/n` 次分解，
所以"低精度更快"只在 `n > 12k`（FP32）或 `n > 6.9k`（11 位）时成立。
`n=64` 的 11 位 + GMRES 会慢一倍。**这决定了产品的形态**：
小 `n` 卖的是面积/能耗（可穿戴、终端基带），大 `n` 卖的是吞吐（数据中心、科学计算）。

## 6.3 数据流：面板 / 更新分离

分块 LU（[02 篇 A4](02-算法族谱.md)）天然匹配"两种精度、两种阵列"：

```
for k = 0 : b : n-1
    ┌─────────────────────────────────────────┐
    │ 1. 面板分解  A[k:k+b, k:k+b] → LU       │  高精度小阵列（FP64/FP32）
    │ 2. 面板三角求解  L21 = A21 U11⁻¹        │  高精度
    │ 3. 行交换应用到 A12 与 A22              │  纯数据搬运
    │ 4. 尾块更新  A22 -= L21 · U12           │  ★ 低精度大阵列（O(n³) 在这里）
    └─────────────────────────────────────────┘
```

第 4 步占 90% 以上的 flops，也是唯一值得为它扩阵列的一步。
`b` 的选择是"面板开销 vs 更新效率"的折中，典型 `b=64–256`。

**精度切换的成本**：面板与更新之间要转换 `b×b` 与 `b×(n-k)` 的数据。
每块转换 `O(bn)` 个元素，总计 `O(n²)` 次转换——相对 `O(n³)` 的更新可以忽略，
但**不要在更新的内层循环里逐元素转换**（那会把流水线打穿）。

## 6.4 四条设计规则

> **R1 只降 `O(n³)` 的精度。** 其余三个槽位降了也省不出时间，反而把误差锚点弄丢。
>
> **R2 `u_r` 必须是全精度，且是芯片上唯一的 FP64 通路。** 它决定"能恢复到多准"，
> 而且它的算力需求只有 `O(n²)`。
>
> **R3 要低精度就重算，不要压缩。** 低精度重算自带正则化（[03 篇 3.4](03-误差理论与可行域.md)），
> 压缩高精度因子会保留病态谱，让 GMRES 失效。
>
> **R4 算力受限降 `u_f`，带宽受限降 `u_s`。** 前者换峰值算力，后者换容量/带宽。
> 稠密大 `n` 是前者，稀疏/小 `n`/多右端是后者。

## 6.5 一个具体的架构草图

```
                    ┌──────────────────────────────┐
   b (n×1)  ───────▶│  FP32/11 位 GEMM 阵列 (主)   │  90% 面积
                    │  tile LU 的尾块更新           │  2×–8× 峰值
                    └──────────────┬───────────────┘
                                   │ L̂, Û (FP32 存储)
                    ┌──────────────▼───────────────┐
                    │  三角求解单元 (FP32/FP64)     │  ~2%
                    └──────────────┬───────────────┘
                    ┌──────────────▼───────────────┐
   x (n×1)  ◀───────│  残差/精化单元 (FP64)         │  ~3%
                    │  r = b - Ax;  x += d          │
                    │  κ 估计; GMRES 正交化         │
                    └──────────────────────────────┘
```

三点说明：

1. **主阵列按 `u_f` 设计**，用 FP32 还是 11 位取决于目标 `κ` 与吞吐比。
2. **残差单元是全芯片唯一的 FP64 部件**，只需要向量乘加，不需要矩阵能力。
3. **GMRES 的正交化**（`O(n·k)` 内积）在 FP64 下做，放在控制通路里，面积小但影响收敛。

## 6.6 Roofline：什么时候降精度没用

LU 的算术强度（无分块）：

```
AI = flops / bytes ≈ (2/3 n³) / (2n² · 8B) = n/24  flops/byte      (FP64)
```

- `n=1024`：AI ≈ 43，低于 FP64 的机器平衡点（H100 ≈ 34 TFLOPS / 2 TB/s ≈ 17）——**算力受限**。
- `n=256`：AI ≈ 11，**带宽受限**；此时降 `u_f` 不加速，**降 `u_s`（因子存 FP32）才加速**。
- 稀疏 LU：AI 更低，几乎总是带宽受限。

**这就是 R4 的由来**：稠密大 `n` 走"降 `u_f`"，稀疏/小 `n` 走"降 `u_s`"。
本文实验里 `q24_ir`（因子存 FP32 + 定常 IR）在 `κ=1e14` 仍然可用（[04](04-实验证据.md)），
意味着**存储量化几乎不损失可行域**——这是性价比最高的一档。

## 6.7 精度切换的三个坑

1. **转换不是免费的**：FP32→FP64 的转换要经过规格化/移位，吞吐通常只有 FMA 的 1/4–1/2。
   把转换放在 `O(n³)` 内层会吃掉收益；放在 `O(n²)` 的边界上则无感。
2. **累加器精度**：张量核的 FP32 累加器在 `n` 大时会掉精度（`n·u` 累积）。
   若 `u_f=11 位`，累加器至少 FP32，且要定期"刷新"（分段累加）。
3. **非规格化数/上溢**：半精度下 `U` 的对角元可能下溢到 0（尤其病态矩阵），
   需要缩放（equilibration）或显式的"小主元处理"。Scott & Tůma
   [专门讨论了这个问题](https://arxiv.org/abs/2401.17957)。

## 6.8 与"纯 FP64 芯片"的对比

| 指标 | 纯 FP64 | 本文方案（FP32 主 + FP64 精化） |
|---|---|---|
| 峰值算力 | 1× | 2×（FP32 阵列） |
| 面积 | 1× | ~0.55×（FP64 只占 3–5%，主阵列每 FMA 省 3/4） |
| 能效 (flops/W) | 1× | ~2× |
| 可用 `κ` | 任意 | `<1e14`（FP64 本身也是这个范围） |
| 编程模型 | 直接求解 | 需要"分解 + 精化"两段，多一层调度 |

面积估算：若主阵列占 90% 面积、FP64 单价 4×、FP32 单价 1×，
则 `0.9/4 + 0.1 ≈ 0.33`——**理论上可省 2/3 面积**，代价是多一层精化调度。

## 6.9 本篇小结

1. 高精度只需存在于 `O(n²)` 的残差/精化通路，面积占比随 `n` 增大而下降（`~12k/n`）。
2. 分块 LU 天然给出"面板高精度、更新低精度"的切分，是硬件落点。
3. 四条规则：只降 `n³`、残差全精度、重算不压缩、按瓶颈选槽位。
4. 小 `n`（<256）时 FP64 占比反而高，此时要么直接用 FP64，要么用 11 位把迭代数压下来。
